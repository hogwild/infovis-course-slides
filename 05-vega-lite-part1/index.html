Notes: 2 min. This is a reference page immediately after the filter example, not a requirement to learn every transform now. View-level transforms execute in array order before the encoding-level operations. For example, encoding.y.aggregate: "mean" is shorthand; an explicit aggregate transform instead uses aggregate: [{op: "mean", field: "Miles_per_Gallon", as: "mean_mpg"}], groupby: ["Origin"], and the encoding then reads mean_mpg. Do not paste the encoding shorthand directly into the transform array. bin and timeUnit derive values without by themselves summarizing records or counting frequencies. fold preserves original fields while adding key/value fields to the generated rows. lookup matches a key to a secondary source. window needs suitable operation, sort, and frame settings for the intended rank, cumulative sum, or moving average. Additional transforms, including joinaggregate, pivot, flatten, and regression, are available through the linked documentation. [Sources] https://vega.github.io/vega-lite/docs/transform.html; https://vega.github.io/vega-lite/docs/aggregate.html; https://vega.github.io/vega-lite/docs/calculate.html; https://vega.github.io/vega-lite/docs/bin.html; https://vega.github.io/vega-lite/docs/timeunit.html; https://vega.github.io/vega-lite/docs/fold.html; https://vega.github.io/vega-lite/docs/lookup.html; https://vega.github.io/vega-lite/docs/window.html

Each displayed object is the value of filter, not a complete specification or transform entry: write transform: [{filter: CONDITION}] using one of these objects. equal keeps Japan records; not around equal keeps the other origins. There is no unequal predicate key. lt is strict less-than and lte includes equality; gt is strict greater-than and gte includes equality. The two numeric examples use Cylinders, a numeric field present in every Cars record, so missing values do not distract from comparison boundaries. range includes both 80 and 120. oneOf uses a capital O. valid: true excludes invalid field values such as null, undefined, and NaN; unlike aggregate: "valid", it keeps records rather than counting them. For fields with missing values, explicitly check valid when numeric comparisons should exclude missing data. Logical and/or take arrays of conditions; not takes a single condition. Expression strings are another supported form, for example filter: "datum.Origin !== 'Japan'", but object syntax keeps this reference consistent with the first filter example.
